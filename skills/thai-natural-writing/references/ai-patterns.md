# Thai AI writing patterns & Humanizer guide

Rule: Do not delete or rewrite mechanically. If removing or changing a phrase preserves the original facts, removes robotic AI markers, and reads naturally to a Thai native speaker, change it. If a phrase does real semantic work in the sentence, keep it.

---

## Category A: Staging instead of stating (ลีลาลีลาล้นแต่ไร้สาระ)

AI language models frequently signal significance rather than stating facts directly.

### 1. "Not X, but Y" (ไม่ใช่แค่ X แต่คือ Y)
- **Watch for:** ไม่ใช่แค่... แต่ยัง..., ไม่ใช่เพียงแต่... หากแต่..., ไม่ใช่เรื่องของ... แต่มันคือ..., X แทนที่จะเป็น Y
- **Problem:** สร้างความขัดแย้งเทียมเพื่อยกให้อีกส่วนดูยิ่งใหญ่ ทั้งที่ไม่มีใครอ้างแบบแรกมาก่อน
- **❌ Before:** ไม่ใช่แค่การเขียนโค้ด แต่คือการสร้างสรรค์ผลงานแห่งอนาคต
- **✅ After:** เป็นการเขียนโค้ดสำหรับระบบงานระยะยาว
- **❌ Before:** ไม่ใช่แค่เร็ว แต่ยังปลอดภัยอย่างแท้จริง
- **✅ After:** ทำงานเร็วและปลอดภัย

### 2. Dramatic one-line closers (สรุปปิดท้ายทิ้งท้ายแบบดราม่า)
- **Watch for:** "และนั่นคือจุดเปลี่ยน", "จำประโยคนี้ไว้ให้ดี", "นี่คือชัยชนะที่แท้จริง", "และนั่นคือบทเรียนราคาแพง", "ไม่มีข้ออ้าง ไม่มีข้อแม้"
- **Problem:** ประโยคเดี่ยวๆ สั้นๆ ที่คอยสั่งให้ผู้อ่านหยุดซาบซึ้ง แทนที่จะให้ข้อมูลใหม่
- **❌ Before:** เราลดรอบการ Deploy ลงเหลือ 5 นาที นั่นคือจุดเปลี่ยนสำคัญของทีม
- **✅ After:** เราลดเวลา Deploy ลงเหลือ 5 นาที ทำให้ทีมปล่อยฟีเจอร์ได้เร็วขึ้น

### 3. Deep-sounding sayings & hollow aphorisms (คำคมลึกซึ้งแต่กลวง)
- **Watch for:** "หัวใจสำคัญคือ...", "ในโลกความเป็นจริง...", "สิ่งสำคัญที่สุดไม่ใช่...", "...คือเหรียญสองด้าน", "...คือกระจกสะท้อน...", "...กลายเป็นกับดัก"
- **Problem:** เอาเรื่องธรรมดามาแปลงเป็นคำคมสอนใจ หรือพยายามทำตัวเป็นนักปราชญ์
- **❌ Before:** ความเร็วกลายเป็นกับดัก เมื่อทีมลืมให้ความสำคัญกับคุณภาพ
- **✅ After:** การเร่งทำงานอาจทำให้คุณภาพโค้ดลดลง หากไม่มีการเขียนเทสต์ที่ดี

### 4. Staged run-up & false candor (เกริ่นลีลาก่อนเข้าเรื่อง)
- **Watch for:** "มาเจาะลึกกันเลย", "สิ่งที่คุณต้องรู้คือ...", "เอาตรงๆ นะ", "ก่อนอื่นเลย", "โดยไม่รอช้า", "ปฏิเสธไม่ได้ว่า...", "ในยุคที่..."
- **Problem:** เกริ่นประกาศว่าจะพูด หรือแกล้งทำเป็นเปิดอกคุย แทนที่จะบอกเนื้อหาตรงๆ
- **❌ Before:** มาเจาะลึกกันเลย สิ่งที่คุณต้องรู้เกี่ยวกับ Redis Cache คือ...
- **✅ After:** Redis Cache ทำหน้าที่เก็บข้อมูลในหน่วยความจำเพื่อ...
- **❌ Before:** ในยุคที่เทคโนโลยีก้าวหน้า ปฏิเสธไม่ได้ว่าความปลอดภัยเป็นเรื่องสำคัญ
- **✅ After:** ความปลอดภัยของระบบเป็นเรื่องสำคัญ

### 5. Arguing with no one / fake objections (โต้แย้งสิ่งที่ไม่มีใครพูด)
- **Watch for:** "ไม่ได้บอกว่า... ไม่สำคัญ", "หลายคนอาจคิดว่า... แต่...", "อาจมีคนแย้งว่า..."
- **Problem:** ยกข้อโต้แย้งที่ไม่มีใครทักท้วงขึ้นมาแก้ต่างเอง ทำให้ยืดยาวและเสียประเด็น
- **❌ Before:** ไม่ได้บอกว่าเอกสารไม่สำคัญ แต่สิ่งที่สำคัญกว่าคือระบบที่ทำงานได้จริง
- **✅ After:** ทีมให้ความสำคัญกับการพัฒนาระบบให้ใช้งานได้จริงควบคู่ไปกับการทำเอกสาร

## Category B: Rhythm by rule (จังหวะแบบหุ่นยนต์)

### 6. Forced triads (จัดกลุ่มสามสิ่งเสมอ)
- **Watch for:** การจัดคำคุณศัพท์หรือคำนามเป็น 3 ก้อนติดกันเสมอ ("รวดเร็ว ปลอดภัย และมีประสิทธิภาพ", "เข้าใจง่าย ยืดหยุ่น และทรงพลัง")
- **Problem:** AI ถูกเทรนมาให้สรุปอะไรเป็น 3 อย่างเพื่อให้ฟังดูครบถ้วน ทั้งที่ความจริงอาจมีแค่ 1 หรือ 2 อย่าง
- **❌ Before:** แพลตฟอร์มนี้มอบความสะดวกสบาย ความแม่นยำ และความคุ้มค่า
- **✅ After:** แพลตฟอร์มนี้ช่วยให้ค้นหาข้อมูลได้สะดวกและแม่นยำ

### 7. Repeated sentence openings (ขึ้นต้นประโยคซ้ำซาก)
- **Problem:** ทุกประโยคในย่อหน้าขึ้นต้นด้วยโครงสร้างเดียวกัน เช่น "ระบบจะ...", "ระบบจะ...", "ทีมงานได้ทำการ...", "ทีมงานได้ทำการ..."
- **Fix:** รวบประโยค หรือสลับเอาผลลัพธ์/การกระทำขึ้นก่อน

### 8. Em-dashes as universal connectors (การใช้ขีดกลาง — พร่ำเพรื่อ)
- **Problem:** ภาษาอังกฤษมักใช้ `—` (em-dash) เชื่อมประโยค แต่ในภาษาไทยการใส่ขีดกลางยาวๆ ทำให้อ่านสะดุดและดูเป็นภาษาแปลเครื่อง
- **Fix:** เปลี่ยนเป็นเครื่องหมายจุลภาค (,), วงเล็บ, ขึ้นประโยคใหม่, หรือใช้คำเชื่อมภาษาไทยที่เหมาะสม (เช่น "ซึ่ง", "โดย", "ที่")

### 9. Stacked qualifiers & excessive hedging (คำบอกขอบเขตซ้อนกัน)
- **Watch for:** "อาจมีความเป็นไปได้ว่าน่าจะส่งผล...", "ในบางกรณีอาจกล่าวได้ว่า..."
- **Fix:** ตัดให้กระชับเหลือความหมายที่แท้จริง: "อาจส่งผลกระทบ..."

### 10. Passive voice & awkward translations (สำนวนถูกกระทำแบบฝรั่ง)
- **Watch for:** "ถูก... โดย..." ในบริบทที่ไม่ใช่เรื่องร้าย (ภาษาไทยมักใช้ "ถูก" กับเรื่องทางลบ), "ได้รับการ...", "มีการ..."
- **❌ Before:** ฟังก์ชันนี้ถูกพัฒนาโดยทีม Frontend และถูกทดสอบโดย QA
- **✅ After:** ทีม Frontend พัฒนาฟังก์ชันนี้ และทีม QA เป็นผู้ทดสอบ
- **❌ Before:** โค้ดได้รับการปรับปรุงให้มีประสิทธิภาพ
- **✅ After:** เราปรับปรุงโค้ดให้ทำงานได้ดีขึ้น

## Category C: Inflation & borrowed authority (คำยกยอเกินจริงและการอ้างลอยๆ)

### 11. Overused Thai AI buzzwords (คำฮิตติดปาก AI)
| คำ AI | ปัญหา | คำที่ควรใช้แทน |
|---|---|---|
| **ยกระดับ** | คำนามธรรมเกินจริง | "ปรับปรุง", "ทำให้ดีขึ้น", "ช่วยให้... เร็วขึ้น" |
| **ขับเคลื่อน** | ใช้จนเกร่อ | "ผลักดัน", "ช่วยให้", "ใช้..." |
| **ตอกย้ำ** | คำขายของ | "ยืนยัน", "แสดงให้เห็นว่า", หรือตัดออก |
| **ตอบโจทย์** | คำครอบจักรวาล | ระบุชัดเจนว่าแก้อะไรได้ เช่น "ตรงกับความต้องการของลูกค้า" |
| **ครอบคลุม** | ใช้ซ้ำซาก | "ครบทุกขั้นตอน", หรือระบุสิ่งที่ครอบคลุม |
| **อย่างแท้จริง** | คำเสริมน้ำหนักไร้สาระ | ตัดออกได้ทันที |
| **ทรงพลัง** | เกินจริง | "มีประสิทธิภาพสูง", "รองรับงานหนักได้" |
| **ไร้รอยต่อ** | คำโฆษณา | "เชื่อมต่อกันได้ทันที", "ไม่ต้องสลับหน้าจอ" |
| **พลิกโฉม / นิยามใหม่** | อภิมหาคำเคลม | "เปลี่ยนวิธีทำงาน", "รูปแบบใหม่" |

### 12. Padded verbs (กริยาฟุ่มเฟือย)
| ❌ คำฟุ่มเฟือย | ✅ คำตรงประเด็น |
|---|---|
| ดำเนินการ + verb | "ดำเนินการตรวจสอบ" → **"ตรวจสอบ"** |
| ทำการ + verb | "ทำการแก้ไข" → **"แก้" / "ปรับปรุง"** |
| มีความสามารถในการ + verb | "มีความสามารถในการประมวลผล" → **"ประมวลผลได้"** |
| ในส่วนของ X | **"ฝั่ง X" / "ส่วน X"** หรือตัดออก |
| X ดังกล่าว | **"X นี้"** หรือระบุชื่อ X ซ้ำ |
| เป็นการ + verb | ตัด "เป็นการ" ออก |

*หมายเหตุ: คำว่า "ดำเนินการ" อนุโลมให้ใช้ได้เฉพาะระเบียบการทางราชการหรือกฎหมายเท่านั้น สำหรับงานเทคนิคและธุรกิจทั่วไปให้ตัดทิ้ง*

### 13. Inflated significance (ยกความสำคัญยิ่งใหญ่เกินจริง)
- **Watch for:** "ถือเป็นหมุดหมายสำคัญ", "สะท้อนภาพรวมแห่งความสำเร็จ", "ปูทางสู่อนาคต", "แม้จะเผชิญความท้าทาย... แต่ก็ยังคงเติบโตอย่างมั่นคง"
- **Fix:** พูดข้อเท็จจริงล้วนๆ แล้วจบที่ผลลัพธ์ ไม่ต้องแถมประโยคชื่นชมตัวเอง

### 14. Dangling participle / shallow -ing riders ("สะท้อนให้เห็นว่า...")
- **Watch for:** ประโยคท้ายห้อยด้วย "...สะท้อนให้เห็นถึงความมุ่งมั่น", "...ตอกย้ำความเป็นเลิศ", "...ส่งผลให้เกิดการพัฒนาที่ยั่งยืน"
- **Fix:** ตัดประโยคห้อยท้ายนี้ออก

### 15. Borrowed authority (อ้างผู้เชี่ยวชาญแบบลอยๆ)
- **Watch for:** "ผู้เชี่ยวชาญระบุว่า...", "รายงานหลายฉบับชี้ว่า...", "เป็นที่ยอมรับกันอย่างแพร่หลายว่า..."
- **Fix:** หากไม่มีชื่อแหล่งอ้างอิงชัดเจน ให้ระบุข้อเท็จจริงตรงๆ หรือตัดคำอ้างลอยๆ ออก

### 16. Avoiding "เป็น / อยู่ / คือ"
- **Watch for:** "ทำหน้าที่เป็น...", "ถือได้ว่าเป็น...", "มีบทบาทสำคัญในการเป็น..."
- **Fix:** ใช้ "เป็น" หรือ "คือ" ตรงๆ
- **❌ Before:** Redis ทำหน้าที่เป็นตัวกลางในการเก็บ Session
- **✅ After:** เราใช้ Redis เก็บ Session หรือ Redis เป็นตัวเก็บ Session

## Category D: Formatting by rule (การจัดรูปแบบตายตัวเกินไป)

### 17. Bold labels on every bullet (ตัวหนาทุกบรรทัดแบบหุ่นยนต์)
- **Problem:** ลิสต์รายการสั้นๆ ทุกข้อใส่ตัวหนาตามด้วยโคลอน เช่น
  - **ความเร็ว:** เร็วขึ้น 20%
  - **ความปลอดภัย:** ปลอดภัยขึ้น
  - **ความสะดวก:** ใช้งานง่าย
- **Fix:** หากเนื้อหาสั้น ให้เขียนรวบเป็นประโยคธรรมดา หรือไม่ต้องใส่ป้ายตัวหนาพร่ำเพรื่อ

### 18. Emojis and decorative headings (อีโมจิและหัวข้อแฟนซี)
- **Watch for:** 🚀 **การเปิดตัว:**, 💡 **ข้อคิดสำคัญ:**, 📌 **สรุป:**, 🔥 **ไฮไลท์:**
- **Fix:** ตัดอีโมจิออกทั้งหมดในเอกสารที่เป็นทางการ รายงาน หรือ README ของวิศวกร ใช้ heading ปกติ

## Category E: Leftovers from chat & draft (เศษซากคำตอบ AI)

### 19. Chatbot residue (คำเกริ่นและคำลงท้ายของ AI)
- **Watch for:**
  - "แน่นอนครับ/ค่ะ!", "ยินดีช่วยครับ!", "ด้วยความยินดีครับ"
  - "หวังว่าข้อมูลนี้จะเป็นประโยชน์นะครับ", "หากมีข้อสงสัยเพิ่มเติมสอบถามได้เลยครับ"
  - "ต่อไปนี้คือข้อความที่ได้รับการเกลาแล้ว:"
- **Fix:** ตัดทิ้งทั้งหมด ให้เหลือเฉพาะเนื้อหาผลงานจริงที่พร้อมนำไปใช้

### 20. Self-narration (เขียนบรรยายตัวเอกสารแทนที่จะบอกเนื้อหา)
- **Watch for:** "เอกสารฉบับนี้จัดทำขึ้นเพื่อชี้แจง...", "ตารางด้านล่างนี้จะแสดงให้เห็นถึง..."
- **Fix:** เข้าประเด็นทันที หรือตัดคำอธิบายการจัดวางหน้าออก

## Category F: Writing for the wrong reader (บริบทไม่เหมาะกับผู้อ่าน)

### 21. Re-explaining what the reader already knows (ทวนเรื่องที่เขารู้อยู่แล้ว)
- มักพบในการตอบ Slack/Email สั้นๆ, PR Description, หรือ Commit Message ที่ AI ชอบทวนว่า "จากปัญหาที่เคยเกิดขึ้นในอดีตเรื่อง..."
- **Fix:** ขึ้นต้นด้วยการตัดสินใจ ผลการทดสอบ หรือสิ่งที่ทำเสร็จทันที (Decision first)
